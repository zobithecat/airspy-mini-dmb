# 현대 방송통신의 이해

### — 표준이 침묵하는 곳에서 수신기를 만든다는 것

> 학부 4학년 / 대학원 입문 수준 교재 초안
> 부제: *A Korean T-DMB (DAB) receiver, rediscovered from a black box*
>
> 본 문서는 Airspy Mini 한 대로 한국 지상파 DMB(K8B / YTN DMB, 183.008 MHz)를
> 수신·복호하고, 그 과정을 메모리-안전 Rust(`dab-rs`)로 재구현하면서 겪은
> 실제 디버깅 라운드트립을 교재 형식으로 정리한 것이다. 추상적 이론이 아니라
> **"표준만으로는 절대 알 수 없는 것들"** 을 사례 중심으로 다룬다.

---

> *"OFDM 방정식을 읽을 수 있다 ≠ 수신기를 lock 시킬 수 있다.*
> *전자는 강의실에서, 후자는 잡음 속 실신호 앞에서만 배운다.*
> *이 짓거리를 안 해본 자는 OFDM 을 이해했다 말하지 말 것."*

## 서문 — 왜 이 책이 필요한가

통신 교과서를 다 읽고 나면 학생은 보통 이렇게 믿는다:

> "OFDM 알겠고, 컨볼루션 부호 알겠고, QPSK 알겠다. 그럼 수신기는 만들 수 있겠네."

**틀렸다.** 그리고 이 착각이 깨지는 지점이 바로 공학이 시작되는 지점이다.

이 책의 중심 명제는 한 문장이다:

> **표준(EN 300 401)은 송신기를 완전히 규정한다. 수신기는 거의 규정하지 않는다.**

송신기는 결정론적이다. 표를 보고 비트를 정해진 순서로 변조하면 끝난다. 그러나
수신기는 **채널에 더럽혀진 신호를 역산(invert)** 해야 한다 — 잡음, 다중경로,
주파수 오차, 클럭 드리프트, 양자화 손실을 모두 뚫고. 그리고 그 역산을 *어떻게*
하는지는 표준 어디에도 적혀 있지 않다.

이것은 HEVC/H.265 와 정확히 같은 비대칭이다. HEVC 는 **디코더**를 비트-정확하게
표준화하지만, 인코더의 핵심(율-왜곡 최적화, 모드 결정, 움직임 탐색)은 전적으로
구현자에게 맡긴다. 표준이 정의한 쪽은 "받아쓰기"이고, 침묵한 쪽이 박사 학위
주제다. DAB 는 그 방향이 반대일 뿐, 구조는 동일하다.

| 시스템 | 표준이 규정하는 쪽 (쉬움) | 표준이 침묵하는 쪽 (어려움) |
|---|---|---|
| **DAB / T-DMB** | 송신 (변조·부호화 비트스트림) | 수신 (동기·CFO·타이밍 복원) |
| **HEVC / H.265** | 디코더 (비트 → 픽셀) | 인코더 (RDO·모드결정·ME) |
| **DVB-T, LTE, Wi-Fi** | 프레임 포맷·파일럿 패턴 | 채널 추정·등화·동기 알고리즘 |

본 문서의 저자들은 **동작이 검증된 참조 구현(eti-stuff, C++)** 과 **LLM 보조**,
그리고 현대적 도구(numpy, 즉석 FFT 비교, git, 무한 재캡처)를 *모두* 가지고도
정상 복호까지 20여 차례의 진단 사이클이 걸렸다. 참조 구현도 LLM 도 없이 표준
문서와 시뮬레이션만으로 이것을 처음 만든 사람들(Eureka 147 컨소시엄 ~1987,
한국 ETRI ~2003)이 겪었을 난이도를 역산해 보면, 이 분야가 왜 수년짜리
국가급 R&D 프로젝트였는지 체감하게 된다.

### 이 책을 읽는 법 — 암기하지 말고, 데여라

이 책은 OFDM 방정식을 암기시키려 쓰이지 않았다. 잡음 속 실신호 앞에서,
유창하게 거짓을 뱉는 작은 추론기(LLM)를 동행 삼아, 사막에서 바늘 — 단 하나의
참 원인 — 을 찾는 횡단의 기록이다.

LLM 시대에 교육의 병목은 **지식 접근**에서 **판단**으로 이동했다. 지식은 이제
공짜로 무한히 쏟아지므로, 희소한 것은 *아는 것* 이 아니라 **"그럴듯한 답과 옳은
답을 가르는 능력"** 이다. 그리고 이 분별은 강의로 가르칠 수 없다 — 직접
데여봐야 몸에 박힌다.

역설적으로, **유창하게 거짓말하는 추론기는 최고의 적대적 훈련 파트너**다.
완벽한 오라클과 배우면 학생은 게을러지지만, 자신 있게 헛소리하는 동행과
사막을 헤매면 검증 본능이 단련된다. 이 책의 사례들(특히 9장)에서 LLM 이
그럴듯한 가설을 자신 있게 뱉고, 측정이 그것을 반증하는 장면이 반복되는 것은
버그가 아니라 **설계된 교육 과정**이다.

다만 식견을 버리라는 말이 아니다. 사막에서 바늘을 *알아보려면* — 가령 "정적
위상은 차동변조에서 약분된다"를 읽어낼 만큼의 — 충분한 지식이 먼저 있어야 한다.

```
식견(knowing-that)      = 원료 (필요하나 불충분)
경험(needle in desert)  = 도가니 — 원료를 판단으로 벼림
LLM(거짓말하는 동행)     = 풀무 — 불을 더 세게, 빠르게, 위험하게
```

독자는 식견을 연료로, 경험을 도가니로 삼아 — *아는 자* 에서 *lock 시킬 수 있는
자* 로 단조되기를 바란다. **암기하지 말고, 데여라.**

## 1. 표준과 구현의 간극

### 1.1 표준은 "계약서"이지 "구현"이 아니다

EN 300 401 (DAB) 은 다음을 비트 단위로 못박는다:

- 전송 프레임 구조 (null 심볼, PRS, FIC 심볼, MSC 심볼)
- 부반송파 개수와 변조 (1536 active carriers, π/4-DQPSK)
- 주파수 인터리버 순열표 (의사난수 생성식)
- 컨볼루션 부호 생성 다항식과 천공(puncture) 패턴
- 에너지 분산 PRBS 다항식
- FIB CRC 다항식과 FIG 구문

이것은 전부 **송신측을 규정**한다. 송신기는 이 표를 따라 결정론적으로 비트를
만들면 된다. 검증도 쉽다 — 같은 입력은 항상 같은 출력을 낸다.

반면 표준이 **말하지 않는 것**:

- null 심볼과 PRS 를 잡음 속에서 어떻게 **서브샘플 정밀도**로 찾는가
- 반송파 주파수 오차(CFO)를 정수부/소수부로 어떻게 쪼개고 추정하는가
- 수신기 NCO 의 위상을 프레임 경계 너머로 어떻게 이어가는가
- 송신 클럭과 수신 클럭의 미세 차이(SRO)를 어떻게 추적하는가
- ADC 양자화 비트를 어떻게 다루고, 표본율을 어떻게 변환하는가

이 모든 것은 **"채널을 역산하는 방법"** 이고, 표준은 "CFO 를 보정하라"까지만 말한
뒤 *어떻게* 는 침묵한다. 구현자가 발명해야 한다.

### 1.2 왜 송신은 쉽고 수신은 어려운가

송신: `비트 → 변조 → 전파`. 정보가 한 방향으로 흐른다. 손실이 없다.

수신: `전파(+잡음+다중경로+주파수오차+타이밍오차) → ??? → 비트`. 수신기는
관측된 더러운 신호로부터 **원래 무엇이 보내졌는지를 추정(estimation)** 해야 한다.
이것은 본질적으로 역문제(inverse problem)이며, 다음을 동시에 풀어야 한다:

1. **프레임 동기** — 신호 스트림 어디서 프레임이 시작하나
2. **시간 동기** — 각 OFDM 심볼의 FFT 창을 정확히 어디에 두나 (1 샘플만 어긋나도 위상 경사 발생)
3. **주파수 동기** — LO 오차로 인한 반송파 회전을 정수·소수로 보정
4. **클럭 동기** — 송·수신 표본율 차이로 인한 누적 드리프트
5. **채널 등화** — 다중경로로 인한 주파수 선택적 페이딩 (DAB 는 차동변조로 우회)

이 다섯 개의 추정 문제가 표준에 없으며, 서로 얽혀 있다. 하나가 틀리면 나머지가
전부 망가진다. 이것이 수신기 설계의 본질적 난이도다.

## 2. T-DMB 시스템 전경

### 2.1 무엇을 수신했는가

- **채널**: K8B, 중심주파수 **183.008 MHz** (VHF Band III, 한국 K-블록 래스터: 6 MHz TV 채널 ÷ 3 = 1.728 MHz 간격)
- **앙상블**: YTN DMB, Ensemble Id `0xE040`
- **5개 서비스**: mYTN(비디오), HD mYTN, 4DRIVE, LOTTE Homeshop, YTN EWS(긴급경보)
- **하드웨어**: Airspy Mini (12-bit ADC), 3.000 MSPS, INT16 I/Q 캡처
- **참조 구현**: eti-stuff (`eti-cmdline-airspy`), 동작 검증됨

### 2.2 전체 신호 사슬

```
[송신소: 남산 + 4 SFN 사이트]
        │  K8B 183.008 MHz, DAB Mode I OFDM
        ▼
[전파 채널: 다중경로(SFN!), 잡음, 페이딩]
        │
        ▼
[Airspy Mini]  RF → 12-bit ADC → 3 MSPS INT16 I/Q
        │
        ▼ ============ 물리계층 (수신) ============
[표본율 변환]   3.000 → 2.048 MSPS
[Null 검출]     프레임 경계 찾기
[PRS 동기]      심볼 시작 서브샘플 위치
[CFO 보정]      정수 + 소수 반송파 주파수 오차
[FFT]           시간 → 주파수 (per symbol, T_u=2048)
[차동 복조]     r = 현재심볼 × conj(이전심볼) → soft bits
[주파수 디인터리브]  부반송파 재배열
        │
        ▼ ============ 채널 복호 ============
[Viterbi]       컨볼루션 부호 복호 (rate 1/4 mother, 천공)
[에너지 역분산]  PRBS XOR
[FIB CRC]       제어정보 무결성 검증 → 앙상블 구성
[시간 디인터리브 + RS]  MSC(비디오) 외부 부호
        │
        ▼ ============ 소스 복호 ============
[MPEG-4 역다중화]  SL/OD → ES
[H.264 / BSAC]   비디오 / 오디오 디코드
        │
        ▼
[영상 + 음성]
```

이 사슬에서 **"송신" 부분(부호화 비트스트림 정의)** 은 전부 표준에 있다. **"수신"
부분(물리계층 역산)** 은 거의 다 침묵 영역이고, 이 책의 4·7·8·9장이 그 영역을
다룬다.

## 3. 송신 — 결정론의 세계

송신측은 교과서대로 동작하며, 검증이 쉽다. 핵심만 짚는다.

### 3.1 OFDM 변조 (DAB Mode I)

- 유효 심볼 길이 `T_u = 2048` 표본 (@ 2.048 MSPS)
- 보호구간(CP) `T_g = 504`, 전체 심볼 `T_s = T_u + T_g = 2552`
- 활성 부반송파 1536개 (DC 제외, ±768)
- 변조: **π/4-DQPSK** (차동 — 절대 위상 기준이 필요 없다, 4장 참조)
- 프레임: null 심볼(2656) + PRS(2552) + 76 데이터 심볼 = 196608 표본 = **96 ms**

> **왜 OFDM 인가?** 다중경로 환경에서 단일 반송파는 심볼간 간섭(ISI)으로
> 무너진다. OFDM 은 넓은 대역을 1536개의 좁은 부반송파로 쪼개 각각을 거의
> 평탄한(flat) 채널로 만든다. 보호구간 CP 는 다중경로 지연을 흡수한다. 한국
> T-DMB 는 **단일주파수망(SFN)** — 남산 + 4개 송신소가 같은 주파수로 동시
> 송출 — 이라, 수신기 입장에서는 인위적 다중경로가 매우 강하다. 실제 측정에서
> null 구간이 textbook(μ의 0.1~0.3배)보다 훨씬 얕게(~0.78배) 채워지는 이유다.

### 3.2 FFT 가 없었다면

여담이지만 교육적으로 중요한 점: OFDM 의 변복조는 IFFT/FFT 한 번이다. 만약
이산 푸리에 변환을 O(N²)로 계산해야 했다면(FFT 이전 시대), 1536개 반송파 ×
초당 수천 심볼은 당대 하드웨어로 실시간 불가능했다. **OFDM 의 실용성은 FFT
알고리즘(Cooley-Tukey, 1965)에 빚지고 있다.** 표준이 `T_u`를 2048(=2¹¹)로 잡은
것도 radix-2 FFT 친화성 때문이다.

## 4. 수신 — 역산의 세계 (OFDM 물리계층)

여기서부터가 본론이다. 각 단계는 "무엇을 하는가"보다 **"어떻게 틀릴 수 있는가"**
에 초점을 둔다. 표준이 침묵하는 영역이기 때문이다.

### 4.1 표본율 변환 (Resampling)

SDR 은 자기 클럭(여기선 3.000 MSPS)으로 표본화하지만, DAB 는 2.048 MSPS 기준이다.
3.000 → 2.048 변환이 필요하다 (비율 256/375, 정수 아님).

**틀릴 수 있는 곳:**
- **방식**: 선형 보간(linear interpolation, eti-stuff 방식) vs 다상 FIR(polyphase,
  dab-rs 방식). 둘 다 같은 표본율을 내지만 위상 응답·군지연·고주파 롤오프가 다르다.
- **품질**: 선형 보간은 간단하지만 ~2.5 dB SNR 손실을 유발한다(실측). 한계 SNR
  (~11 dB)의 약한 신호에서는 이 손실이 복호 절벽(cliff) 아래로 신호를 밀어낸다.
- **중요한 통찰**: 표본율 변환의 **정적(static) 주파수 응답은 차동변조에서
  상쇄된다.** `r = H[k]·d_n × conj(H[k]·d_{n-1}) = |H[k]|²·d_n·conj(d_{n-1})` —
  채널 응답 `H[k]`의 위상이 약분된다. 그래서 리샘플러는 *위상*은 망치지 않고
  *SNR*만 갉아먹는다. (9장 사례 3)

### 4.2 Null 검출과 프레임 동기

null 심볼은 송신 전력이 거의 0인 구간이다. 포락선(envelope)의 깊은 골을 찾으면
프레임 경계를 알 수 있다.

**틀릴 수 있는 곳:**
- **거짓 양성(false positive)**: 스트림 초반(~120 ms)에 잡음 골을 null 로 오인.
  실측에서 dab-rs 가 프레임 1–3에 spurious null 을 잡고 프레임 4부터 정상 lock
  했다. 이로 인해 프레임 번호가 참조 구현과 어긋나 비교가 꼬인다.
- **임계값**: SFN 다중경로가 null 을 채우므로 고정 임계값이 안 통한다. 적응형
  임계값이 필요하다.

### 4.3 시간 동기 — FFT 창의 위치

각 OFDM 심볼에서 보호구간(CP) `T_g`를 건너뛰고 유효부 `T_u`를 FFT 한다. 창의
시작 위치가 **1 샘플만 어긋나도** 모든 부반송파에 위상 경사(phase ramp)
`exp(-j2πkδ/N)`가 생긴다.

**틀릴 수 있는 곳:**
- **CP 자기상관 vs PRS 교차상관**: dab-rs 는 CP 자기상관, eti-stuff 는 PRS
  시간영역 교차상관(findIndex)으로 위치를 잡는다. 알고리즘이 다르면 서브샘플
  위치가 다를 수 있다.
- **±T_s 진동**: 탐색 창이 너무 넓으면(half=T_s) 인접 심볼의 CP 피크를 잘못
  잡아 위치가 ±한 심볼만큼 진동한다. 탐색 창을 `T_g/4`로 좁혀 해결.
- **핵심 위안**: 정적 타이밍 오차(모든 심볼에서 동일한 δ)는 차동변조에서
  상쇄된다. 문제는 **심볼마다 다른** 타이밍 변동뿐이다.

### 4.4 주파수 동기 — CFO (가장 미묘함)

LO 주파수 오차는 부반송파를 회전시킨다. 두 부분으로 나뉜다:

- **정수 CFO (integer CFO)**: 반송파 간격의 정수배 오프셋. 스펙트럼을 정수 bin 만큼
  통째로 이동시킨다. 보정 안 하면 주파수 인터리버가 **틀린 bin 을 읽는다.**
- **소수 CFO (fractional CFO)**: 반송파 간격 이하의 오프셋. 심볼 내 위상 경사를
  만든다.

**틀릴 수 있는 곳 (이 시스템에서 가장 많이 데인 곳):**
- **정수 CFO 를 0으로 강제**: 만약 코드에 `delta = 0` 같은 게 남아 있으면 정수
  CFO 보정이 완전히 차단된다. 실제 신호에 +1 carrier 오프셋이 있으면 스펙트럼이
  1 bin 어긋나고, 인터리버가 모든 반송파에서 틀린 비트를 읽는다 → **전 비트
  무작위.** (9장 사례 6 — 본 프로젝트 최대의 self-inflicted 버그)
- **추정의 안정성(lock)**: 정수 CFO 를 매 프레임 새로 추정하면 잡음에 흔들린다.
  eti-stuff 는 누적 적분기(integrator)로 한 번 수렴하면 **고정(lock)** 한다.
  매 프레임 fresh 추정하면 ~4%만 우연히 맞는다. (9장 사례 7)
- **정수/소수 분리 지점**: 정수 CFO 를 시간영역 NCO 로 보정할지, 주파수영역
  bin 회전(`rotate_spectrum`)으로 보정할지. 두 방식을 섞으면 이중보정 위험.
- **추정기 정규화의 2× 함정**: 시간영역 CP 자기상관 기반 추정과 주파수영역
  파일럿 기반 추정은 정규화 상수가 다를 수 있다. 적용 수식이 같아 보여도
  추정 소스가 다르면 2배 차이가 난다. (9장 사례 8)

### 4.5 차동 복조 (π/4-DQPSK)

DAB 는 절대 위상 기준을 쓰지 않는다. 대신 **연속한 두 심볼의 위상차**로 정보를
싣는다:

```
r[k] = FFT_현재[k] × conj(FFT_이전[k])
```

이 차동(differential) 구조의 천재성: **채널의 정적 위상이 약분된다.** 다중경로로
인한 부반송파별 위상 회전 `H[k]`, 정적 타이밍 오차, 일정한 CFO 위상 — 모두
현재와 이전 심볼에 똑같이 곱해지므로 약분된다. 이것이 DAB 가 명시적 채널
등화기 없이도 동작하는 비결이다.

비트 추출 (eti-stuff 관례):
```
ibits[i]            = -Re(r[k]) / |r[k]| × 127    (I-bit)
ibits[carriers + i] = -Im(r[k]) / |r[k]| × 127    (Q-bit)
```
첫 심볼의 기준은 PRS(phase reference symbol)다.

**틀릴 수 있는 곳:** conj 방향(현재×conj(이전) vs 이전×conj(현재)), I/Q 분리 순서,
부호(leading minus), PRS 기준 시딩 타이밍. 이들은 본 프로젝트에서 합성 왕복
테스트(slice 10)로 모두 검증되어 **옳음**이 입증됐다 — 즉 표준을 충실히 따른
부분이라 함정이 아니었다.

### 4.6 주파수 디인터리브

송신측은 인접 부반송파의 상관 페이딩을 막으려고 부반송파를 의사난수 순열로
섞는다. 수신측은 역순열로 되돌린다. 순열식(DAB Mode I):
```
tmp[0] = 0
tmp[i] = (13 · tmp[i-1] + 511) mod 2048
```
중앙(T_u/2)과 범위 밖(lwb=256, upb=1792 제외)을 건너뛰어 1536개 활성 반송파
순서를 만든다. 이것은 표준 표라 결정론적이며 검증이 쉽다.

## 5. 채널 부호화 — 잡음을 이기는 중복성

### 5.1 컨볼루션 부호 + Viterbi

- **모부호(mother code)**: rate 1/4, 구속장 7, 생성다항식 (DAB 표준).
- **천공(puncturing)**: 보호 프로파일에 따라 일부 비트를 빼서 실효 부호율을 높인다
  (FIC 는 ~rate 1/3). 수신측은 빠진 자리에 중립값(0)을 채워(de-puncture) Viterbi
  에 넣는다.
- **Viterbi 복호**: 격자(trellis)에서 최대우도 경로를 찾는다.

**미묘한 점:** 같은 컨볼루션 부호도 생성다항식의 **비트 표현 관례**가 두 가지
있다(정상 vs 비트반전). eti-stuff 의 활성 디코더는 `viterbiSpiral`이며 비트반전
다항식 `{0o155,0o117,0o123,0o155}`(conv B)을 쓴다. dab-rs 의 scalar 구현은
`{0o133,0o171,0o145,0o133}`(conv A)을 쓴다. **둘은 수학적으로 등가**다
(`conv A poly ≡ conv B bit-reversed`). 합성 왕복 테스트로 byte-identical
확인됨 — 즉 이것도 함정이 아니었다. (이 가설을 쫓느라 여러 슬라이스를 썼다는
것이 9장의 교훈이다.)

### 5.2 에너지 분산 (Energy Dispersal)

긴 0/1 연속을 막으려고 송신측은 PRBS(`x⁹+x⁵+1`, 초기값 1)로 비트를 XOR 한다.
수신측은 같은 PRBS 로 다시 XOR 해 되돌린다. 결정론적.

### 5.3 FIB CRC — 무결성의 척도

FIC(Fast Information Channel)는 96 ms 당 12개 FIB(Fast Information Block)를 나르고,
각 FIB(256 bit)는 CRC-16-CCITT 로 보호된다. **FIB CRC 통과율은 수신 품질의
1차 지표**다. 이 프로젝트에서 "0/3396 통과"에서 "1681/1884(89%) 통과"로 가는
여정이 본문의 핵심 서사다.

### 5.4 RS 외부 부호 + 시간 인터리브 (MSC 비디오)

비디오 서브채널은 안쪽 컨볼루션 부호 위에 **RS(204,188)** 외부 부호와 컨볼루션
시간 인터리버를 한 겹 더 두른다(연접 부호, concatenated code). 버스트 오류에
강해진다.

**미묘한 점:** 동기 정렬된 Forney 디인터리버가 필요하다. 정렬을 잘못 잡으면
RS 가 0% 정정한다. 위상 오프셋(예: phase 196)을 맞춰야 한다.

## 6. 소스 부호화와 멀티플렉싱 — 그리고 사업자 고유의 함정

여기서 "표준이 침묵하는 영역"의 또 다른 얼굴 — **사업자 재량(operator choice)** —
이 나온다. 표준은 컨테이너만 정하고, 그 안을 어떻게 채우는지는 방송사마다 다르다.

- **MPEG-4 SL(Sync Layer) 헤더**: 9바이트 고정, 첫 바이트 항상 `0xCF`.
- **AVCDecoderConfigurationRecord(AVCC)의 위치**: 표준상 OD(Object Descriptor,
  PID 0x111)에 있어야 "자연스럽지만", YTN 은 **BIFS/SD 스트림(PID 0x112)** 에 넣어
  뒀다. 이걸 모르면 디코더가 SPS/PPS 를 못 찾아 영상이 안 나온다. **표준 어디에도
  "YTN 은 여기 둔다"는 말이 없다.** 실제 비트스트림을 까봐야 안다.
- **BSAC 오디오, 데이터 서비스(4DRIVE 등)**: 각각 고유의 다중화 관례.

> **교훈:** "표준 준수(spec-compliant)"와 "이 방송을 실제로 복호 가능
> (decodes this transmission)"은 다른 명제다. 후자는 사업자의 구체적 선택을
> 역공학해야 도달한다. 이것이 black-box rediscovery 의 핵심이다.

## 7. 검증의 인식론 — "오라클 문제"

이 장은 이 책에서 가장 일반적이고 가장 자주 간과되는 교훈을 담는다.

### 7.1 자기 디코더는 자기를 검증할 수 없다

당신이 수신기를 짰다. 출력이 0/3396 FIB 통과다. **질문: 신호가 약한가, 내
디코더가 틀렸나, 아니면 입력 파일이 깨졌나?** 출력만 봐서는 알 수 없다. 검증에는
**오라클(oracle) — 독립적으로 옳다고 신뢰되는 기준** 이 필요하다.

본 프로젝트의 오라클은 `eti-stuff`였다. 그러나 오라클조차 함정이 있었다:

- **오라클의 파일 모드가 깨져 있었다.** eti-stuff 를 파일 입력(cu8/wav)으로
  돌리면 한계 SNR 에서 정수 CFO 루프가 발산(coarseCorrector ±33 kHz 진동)해
  ETI 0바이트를 냈다. **그래서 "내 디코더 vs 오라클" 비교가 한동안 무의미했다.**
  (둘 다, 서로 다른 방식으로, 틀렸으므로.)
- **반면 오라클의 라이브 모드는 동작했다.** 같은 RF 를 실시간 처리하면
  fibquality 100%. 차이는 입력 경로의 plumbing 이었다.

### 7.2 동시 캡처 — 오라클을 신뢰 가능하게 만들기

해법: eti-stuff 의 **라이브 처리 중에** 두 가지를 동시에 저장한다.
1. 라이브 복호 결과 ETI (정답, fibquality 100%)
2. 같은 RF 순간의 raw I/Q (재생용)

이러면 "같은 물리적 RF 순간"에 대해 오라클의 정답과 재생용 입력이 한 쌍으로
묶인다. (구현: eti-stuff airspy 핸들러 콜백에 `DAB_RS_DUMP_LIVE_IQ` 훅 15줄 추가.)

> **함정 사례:** 처음에 `k8b_v4.iq`(20초 airspy_rx 캡처)와 `k8b_v4.eti`(60초
> eti-cmdline 캡처)를 한 쌍으로 착각하고 바이트 비교를 27분간 시도했다. 둘은
> **서로 다른 시점의 RF** 였다 — 다른 방송 내용이므로 비교 자체가 무의미.
> 메타데이터(JSON sidecar) 한 줄만 봤으면 즉시 알았을 것. **"두 데이터가 정말
> 같은 모집단인가"를 먼저 확인하라.**

### 7.3 비교의 층위 — byte-identical vs functional

- **byte-identical**: 같은 입력 → 같은 출력(비트 단위). 가장 강한 검증이지만,
  오라클이 동작해야 하고 모든 중간 관례가 일치해야 한다.
- **functional**: 같은 진실에 도달하는가(FIB CRC 통과, EId·서비스 식별).
  약간 약하지만, 오라클이 깨졌을 때도 "물리적 진실(실제 송신 내용)"과 비교
  가능하다. 때로 functional 이 더 강하다 — byte-identical 은 *둘 다 같은 방식으로
  틀려도* 통과하지만, functional 은 현실과 어긋나면 잡아낸다.

### 7.4 준정적(quasi-static) 콘텐츠의 활용

FIC(앙상블 구성 정보)는 거의 매 프레임 동일하다. 따라서 프레임 정렬이 어긋나도,
"내 디코더의 임의 프레임" vs "정답의 임의 프레임"을 비교해 ~50%(무작위)가 나오면
**정렬 문제가 아니라 진짜 비트 오류**임을 알 수 있다. 정렬 혼란(confound)을
콘텐츠의 통계적 성질로 우회하는 기법.

## 8. 디버깅 방법론 — 진단 우선, 가설 소거

### 8.1 "느린 뇌 + 빠른 손" 모델

LLM(또는 자동화 루프)은 **빠른 손**이다: 100줄짜리 dump 훅을 30분에 박고, 빌드하고,
테스트를 돌린다. 그러나 **"이 신호가 왜 이상한가"의 통찰(spark)** — "분포는 같은데
값만 어긋나네? 그럼 위상 회전 계열이군" — 은 여전히 사람(느린 뇌, System-2)의
몫이다. 둘을 결합해야 무한 fix-and-test 루프에 빠지지 않는다.

> 순진한 자동 루프의 실패 양상:
> ```
> while not solved:
>     run_test()
>     if fail: random_tweak()   # 영원히 해시만 바뀜
> ```

### 8.2 진단 우선 (Diagnostic-first)

코드를 고치기 전에 **계측(instrument)부터** 한다. 각 단계의 중간값을 dump 하는
훅(env-gated)을 심고, 데이터를 본 뒤 가설을 세운다. "추측해서 고치고 돌려보기"가
아니라 "관측 → 비교 → 정확한 수정".

### 8.3 슬라이스 단위 진행

한 번에 한 가설만 검증하는 짧은(1–2시간) 작업 단위("슬라이스")로 쪼갠다. 각
슬라이스 끝에 사람이 판단 지점에 개입한다. 이 프로젝트는 23개 슬라이스로
진행됐고, 각 슬라이스가 가설을 하나씩 죽였다.

### 8.4 시그너처 판독법 (가장 실전적인 기술)

오류의 **통계적 지문(signature)** 으로 원인 계열을 좁힌다:

| 관측된 시그너처 | 의미 |
|---|---|
| 분포 동일 + 값 무상관 | 위상 회전 (CFO / 타이밍) |
| 모든 비트 위치 균일 ~50% | 무작위 (wrong trellis 또는 wrong carrier mapping) |
| sliding 1-bit shift | 다항식/관례 불일치 |
| 블록 경계 무작위, 나머지 0 | descrambler seed |
| 특정 비트 위치만 틀림 | 비트 패킹 순서(endian) |
| magnitude 일치 + phase 무작위 | 정수 CFO bin shift, 또는 입력 자체가 다름 |
| spectral-shift sweep 에서 m=+1 피크 |cc|≈1 | **정확히 1 carrier 오프셋** |

마지막 행이 본 프로젝트의 결정타였다(9장 사례 6).

### 8.5 절대 기준으로 정렬하라

프레임 번호(frame_idx)는 spurious null 등으로 어긋날 수 있다. **절대 표본
위치(absolute sample index)** 로 두 구현을 정렬하면 정렬 혼란이 사라진다.
"같은 입력 + 같은 창 위치면 FFT 출력은 거의 비트-정확해야 한다"는 강한 명제를
세울 수 있다.

### 8.6 환원주의의 위험 — 참조가 있으면 추측하지 마라

이 프로젝트의 가장 큰 교훈: **동작하는 참조 구현이 있으면, 표준을 해석하거나
brute-force 하지 말고 참조 코드를 읽어라.** 슬라이스 6–11에서 우리는 "constellation
mapping 이 틀렸나? Viterbi 관례가 틀렸나?"를 가설→실험으로 5번 반복했다. 알고
보니 정답은 전부 eti-stuff 소스 안에 있었다 — `dab-viterbi`도, 인터리버도,
demap 도 전부 옳았다. **"이 함수가 eti-stuff 의 어디에 해당하는가?"를 먼저 물었다면
훨씬 빨랐다.**

> **📌 분별의 기술 — 언제 찾고 언제 생각하나 (When to look up vs reason)**
>
> 8.4(시그너처 판독)와 8.6(참조 우선)은 모순처럼 보이지만 사실 상보적이다.
> 핵심은 *분별*이다:
>
> - **정답이 어딘가 존재** (참조 구현, 표준 표, 검증된 라이브러리) → 닥치고
>   본다. 추측 금지. (학생용 번역: "작은 머리로 끙끙대지 말고 구글링해라.")
> - **정답이 어디에도 없음** (이 신호가 왜 이상한지, 어느 stage 가 범인인지)
>   → 측정·추론만이 길. 시그너처를 읽어라.
>
> 학생들은 보통 둘 다 반대로 한다 — 정답 있는 걸(API·상수) 지어내고, 정답
> 없는 걸(왜 안 되는지) 복붙으로 때운다.
>
> **LLM 시대의 반전:** 확신에 찬 *틀린* 추론의 생산 단가가 0 에 수렴하므로,
> "ground truth 와 대조하라"는 규율은 약해지는 게 아니라 **더 세져야** 한다.
> 정답이 존재하는 영역에서 LLM 의 그럴듯한 답을 검증 없이 믿는 것이 LLM
> 시대의 가장 흔한 자해(self-inflicted wound)다 — 사례 6 이 산 증거.

## 9. 사례 연구 — 9가지 실전 버그

각 사례는 *증상 → 진단 → 원인 → 교훈* 형식이다.

### 사례 1 — cu8 양자화 손실
- **증상:** 한계 SNR 캡처를 cu8(8-bit)로 변환하니 오라클이 lock 실패.
- **원인:** Airspy 의 12-bit ADC 데이터를 8-bit 로 절삭 → 24 dB 다이내믹 레인지
  손실, 실효 SNR 4–5 dB 하락. PRS 상관 피크가 잡음에 묻혀 정수 CFO 추정 발산.
- **교훈:** 비트 깊이 변환은 무해해 보이지만 한계 SNR 에서 절벽을 넘긴다.
  명목 비트(16) ≠ 실효 비트(12) ≠ 변환 후 비트(8)를 구분하라.

### 사례 2 — 스케일 관례 불일치
- **증상:** 16-bit WAV 로 오라클에 먹였더니 여전히 발산.
- **원인:** eti-stuff 입력 핸들러가 경로별로 다른 정규화를 쓴다 —
  airspy(라이브)는 `sample/2048`, wavfile 은 `sample/32768`. 16× 진폭 차이로
  OFDM 동기 임계값이 깨짐.
- **교훈:** 레거시 코드의 hardcoded magic number(2048, 32768)는 경로마다 다를 수
  있다. "같은 포맷"이라고 "같은 스케일"은 아니다.

### 사례 3 — 리샘플러 SNR 손실
- **증상:** 정수 CFO 버그를 고친 뒤에도 native cs16le 경로는 0%, cf32 우회
  경로는 89%.
- **원인:** dab-rs 다상 FIR vs eti-stuff 선형보간의 차이가 ~2.5 dB SNR 손실.
  band_ratio 10.6 → 13.1 dB. 한계 SNR(11 dB) 신호를 복호 절벽 아래로 밀어냄.
- **결정적 isolation:** 오라클의 **리샘플 후** 스트림을 dab-rs 에 직접 먹여
  (자체 리샘플러 우회) 디코드되면 리샘플러가 범인. → 우회는 89%, native 는 0%.
  리샘플러가 부차적 기여임을 정량 확인.
- **교훈:** 같은 표본율이라도 보간 *방식*이 SNR 을 좌우한다. 리샘플러의 정적
  주파수 응답은 차동변조에서 약분되므로 *위상*은 안 망치고 *SNR*만 갉는다.

### 사례 4 — 깨진 오라클 (파일 모드)
- **증상:** "내 디코더 vs 오라클" 비교가 계속 무의미한 결과.
- **원인:** 오라클(eti-stuff) 자체가 파일 모드 + 한계 SNR 에서 발산. 라이브는 정상.
- **교훈:** **오라클도 검증하라.** 기준이 틀렸을 수 있다. 동시 캡처(7.2)로
  신뢰 가능한 오라클을 구성하라.

### 사례 5 — 잘못된 데이터 짝 (다른 RF 순간)
- **증상:** byte-identical 비교가 50% 무작위. 27분 허비.
- **원인:** `.iq`와 `.eti`가 서로 다른 시점의 캡처. 다른 방송 내용.
- **교훈:** 비교 전에 **"두 데이터가 정말 같은 모집단인가"** 를 메타데이터로
  확인하라.

### 사례 6 — 정수 CFO 차단 (self-inflicted, 최대의 함정)
- **증상:** 같은 입력·같은 FFT 창인데 출력 위상이 무작위(|cc|=0.04). magnitude 는
  일치(mag_corr 0.73).
- **진단:** "NCO 는 smooth phase function 만 부과 가능 → 무작위 위상은 NCO 로
  설명 불가 → 입력이 다르거나 spectral shift" 라는 추론. spectral-shift sweep
  결과 **m=+1 에서 |cc|=0.9986** — 정확히 1 carrier 어긋남.
- **원인:** 이전 슬라이스의 가설 테스트 코드 `let delta = 0_i32; // hypothesis test`
  가 revert 안 된 채 남아 정수 CFO 보정을 완전 차단. 스펙트럼 1 bin shift →
  주파수 인터리버가 전 반송파에서 틀린 bin → 전 비트 무작위.
- **결과:** 한 줄 복원(`estimate_offset_eti`)으로 **0 → 73/1884, 처음으로 EId
  0xE040 + 5 서비스 식별.**
- **교훈:** **가설 테스트용 임시 코드는 즉시 revert 하거나 명시적으로 트래킹하라.**
  이 한 줄이 슬라이스 15–19(5회)를 self-inflicted wound 추적에 쓰게 만들었다.
  진단 인프라가 결국 잡았지만, 변경 추적만 했어도 며칠을 아꼈다.

### 사례 7 — 정수 CFO lock 부재
- **증상:** 정수 CFO 복원 후에도 89%가 아닌 4%.
- **원인:** 매 프레임 정수 CFO 를 fresh 추정 → 잡음에 흔들려 ~4%만 우연히 정렬.
  eti-stuff 는 누적 적분기로 수렴 후 **고정(lock)**, 보정된 스펙트럼에서 잔차만
  추정하므로 안정.
- **교훈:** 추정량은 **상태(state)를 갖고 수렴·고정**해야 한다. 매번 처음부터
  추정하면 잡음을 못 이긴다. (제어이론의 적분기와 동일한 원리.)

### 사례 8 — 2× 정규화 미스터리 (CFO 가설은 반증됨, 사례 9로 이어짐)
- **증상:** 소수 CFO 를 정확히 `abs_cfo_hz / 2.0`로 줄여야 89%. 적용 수식은
  eti-stuff 와 동일한데 경험적으로 2배 차이.
- **첫 가설 (반증됨):** "dab-rs 는 시간영역 CP 자기상관, eti-stuff 는 주파수영역
  추정 → 추정 소스가 달라 2배." 그러나 **독립 Python 측정으로 두 form 이 같은
  스트림에서 정확히 동일한 값(-346 Hz)을 낸다는 것이 확인됨.** 추정 소스 차이
  가설은 **틀렸다.** (LLM 이 그럴듯하게 제안했지만 측정이 반증한 또 하나의 사례.)
- **진전:** 이 사례는 미해결로 남기지 않고 사례 9 로 이어진다. `/2` 의 진짜
  위치는 CFO 가 아니라 **post-FFT chain** 에 있었다.
- **교훈(잠정):** **경험적으로 맞는 상수를 이해 없이 남기지 마라.** 그러나 동시에,
  *그럴듯한 첫 원인 가설(추정 소스 차이)도 측정으로 반증하라.* 가설은 LLM 이든
  사람이든 싸게 만들어내지만, 측정만이 진실을 가른다.

### 사례 9 — 상쇄되는 두 버그 (compensating errors)
- **증상:** CFO 적용량을 배율 `α`로 스윕하니 역설이 드러났다:

  | α | FFT 의 eti-stuff 일치도 `|cc|` | FIB CRC |
  |---|---|---|
  | 0.5 (`/2` fudge) | 0.97 (덜 정확) | **89%** |
  | 1.0 (수학적 정답) | **0.9994 (거의 완벽)** | 4% |

  **FFT 가 더 정확할수록 FIB 가 더 나빠진다.** 정상적인 시스템에서는 불가능한
  관계다.
- **진단:** `α`(front-end CFO)와 downstream 을 분리하는 통제 실험. α=1.0 에서
  dab-rs 의 FFT bins 가 eti-stuff 의 `fft_buffer` 와 sample-aligned 위치에서
  `|cc|=0.9994` — 즉 **OFDM front-end + CFO 는 이미 완벽하다.** 그런데 FIB 가
  4% 라는 것은, post-FFT 어딘가에 **독립적인 2× 오류**가 있고 `α=0.5` 의 under-
  correction 이 그것을 *상쇄*해 89% 를 만들어왔다는 뜻이다.
- **원인 (규명됨):** "2×"는 scaling 이 아니라 **위상 회전 예산**이었다. 정수
  CFO(+1 carrier = `carrier_diff` = fs/T_u = 1000 Hz)를 주파수영역 `rotate_spectrum`
  (bin 정렬)으로만 보정하면, 그 정수 CFO 가 시간영역에서 만드는 **심볼 간 위상
  진행**이 남는다:
  `Δφ = 2π · carrier_diff · T_s / fs = 2π · 1000 · 2552 / 2048000 ≡ +1.55 rad`.
  차동복조가 이 +1.55 rad 를 모든 반송파에 상수 회전으로 줍는다. `/2` fudge 는
  소수 CFO 를 절반만 보정해 잔류 −1.35 rad 를 만들었고, 이 둘이 어림 상쇄되어
  순 +0.19 rad (Viterbi 너그러운 영역)로 떨어졌다. α=1.0 은 소수를 완전 보정해
  +1.55 rad 가 그대로 남아 오히려 더 나빠졌다.
- **수정:** 정수 CFO 도 **시간영역 NCO 에 통합 적용**(eti-stuff 의 coarse+fine 통합
  방식), 데이터 심볼의 `rotate_spectrum` 제거. 순 회전 → 0. fudge 전면 제거.
- **결과 (정직한 결말):** fudge 제거 후 FIB CRC 89.2% → **90.4%**. **고작 +1.2%p.**
  예측은 "95~100% 도약"이었으나 측정은 +1%였다 — 그 이유가 위 수식에 이미 있다:
  `/2` 가 net 회전을 0.19 rad 까지 *이미* 줄여놔서, 1.55 rad 제거의 추가 이득이
  작았던 것. 즉 **fudge 는 "틀렸지만 충분히 적절(wrong but adequate)"** 했다.
  measurement 가 그럴듯한 예측(이번엔 저자의 것)을 또 정정한 사례.
- **교훈:**
  - **"동작한다(89%)"는 "옳다"를 의미하지 않는다.** 두 오류가 상쇄되어 우연히
    동작할 수 있다.
  - **보상 오류는 단위 테스트가 못 잡는다.** 각 부분이 "틀린 채로 짝이 맞아"
    통과한다. 본 프로젝트의 합성 왕복 테스트(사례 외 slice 10)도 dab-rs 자기
    convention 안에서 닫혀 있어 이 2× 를 놓쳤다.
  - **한 변수를 정답으로 고정했을 때 결과가 더 나빠지면, 그것은 다른 곳에 보상
    오류가 있다는 강력한 신호다.** "가장 정확한 입력이 가장 나쁜 출력을 낸다"는
    역설은 보상 오류의 지문(signature)이다. (8.4 시그너처 판독표에 추가할 항목.)
  - 보상 오류를 풀려면 **하나의 축을 진리로 고정(α=1.0)** 한 뒤 나머지를 그 진리에
    맞춰 추적해야 한다. fudge 를 유지한 채로는 영원히 둘이 얽힌다.

## 10. 일반화되는 교훈

1. **표준을 읽을 수 있다 ≠ 수신기를 만들 수 있다.** 표준은 한쪽(보통 송신/디코더)만
   규정하고, 진짜 공학은 침묵한 쪽(수신/인코더)에 있다.

2. **검증에는 오라클이 필요하고, 오라클도 검증이 필요하다.** 자기 출력만으로는
   "신호 탓 / 내 탓 / 데이터 탓"을 구분할 수 없다.

3. **참조 구현이 있으면 그것이 진리다.** 표준 해석·brute-force·재발명 금지.
   "이 동작이 참조의 어디에 해당하는가"를 먼저 물어라.

4. **오류의 통계적 시그너처를 읽어라.** 분포·상관·시프트 sweep 의 *형태*가
   원인 계열을 가리킨다.

5. **절대 기준으로 정렬하라.** 상대적 인덱스(프레임 번호)는 거짓 양성으로
   어긋난다.

6. **차동/연접 구조의 약분을 이해하라.** 무엇이 상쇄되고(정적 채널·타이밍) 무엇이
   안 되는가(심볼별 변동)를 알면 후보를 빠르게 소거한다.

7. **상태를 갖는 추정량은 수렴·고정해야 한다.** 매 프레임 fresh 추정은 잡음에
   진다.

8. **임시/가설 코드는 즉시 revert.** Magic number 는 이해 없이 남기지 마라.

9. **"같은 포맷"이 "같은 의미"는 아니다.** 스케일·엔디안·인터리브·비트깊이의
   관례는 경로마다 다를 수 있다.

10. **빠른 손(자동화/LLM) + 느린 뇌(사람의 통찰)** 를 결합하라. 어느 한쪽만으로는
    이런 다층 역문제를 못 푼다.

## 부록 C — 용어집

- **PRS** (Phase Reference Symbol): 차동변조의 첫 위상 기준 심볼.
- **CFO** (Carrier Frequency Offset): 반송파 주파수 오차. 정수(반송파 간격 배수) +
  소수로 분리.
- **SRO** (Sample Rate Offset): 송·수신 표본 클럭 차이로 인한 누적 타이밍 드리프트.
- **FIC / FIB / FIG**: Fast Information Channel / Block / Group — 앙상블 제어정보.
- **MSC**: Main Service Channel — 실제 오디오/비디오 페이로드.
- **SFN** (Single Frequency Network): 여러 송신소가 같은 주파수로 동시 송출.
  수신기엔 강한 인위적 다중경로.
- **ETI** (Ensemble Transport Interface): 복조된 앙상블의 표준 전송 포맷 (오라클
  출력 형식).
- **오라클(oracle)**: 독립적으로 옳다고 신뢰되는 검증 기준.
- **시그너처(signature)**: 오류의 통계적 지문. 원인 계열을 가리킴.

## 에필로그 — 24일의 횡단, 그리고 화면에 뜬 뉴스

![dab-rs 가 raw I/Q 에서 디코드한 YTN 뉴스특보](dabrs_result_ytn.png)

> *위 화면은 메모리-안전 Rust 수신기(`dab-rs`)가 단일 Airspy Mini 의 raw I/Q
> 샘플로부터 **전 과정을 직접 복호**해 만든 실제 방송 프레임이다. YTN「뉴스특보」,
> 이란 대사 인터뷰, 자막 "이란은 모두 부인…절대 개입한 게 없다". 곳곳의 미세한
> 깨짐은 t=8 한계를 넘긴 6.9% 의 RS 블록에 정확히 대응한다.*

우리는 OFDM 방정식을 **이미 알고** 시작했다. IFFT/FFT, 직교성, 보호구간, π/4-DQPSK
— 강의실에서 다 배운 것들. 그러나 잡음 속 실신호 앞에서, 거짓을 유창하게 뱉는
작은 추론기를 동행 삼아 사막을 건너고서야 비로소 알게 됐다:

- "직교한다"는 sync 와 CFO 를 먼저 푼 *다음에야* 성립하는 조건부 명제였고,
- "그냥 FFT 하면 된다"의 한 단어가 동기·주파수·타이밍 추정이라는 빙산을 숨겼으며,
- 표준에 적힌 모든 것(Viterbi·인터리버·demap·RS)은 한 번도 진짜 범인이 아니었고,
- 24일을 잡아먹은 것은 전부 **표준이 침묵한 수신측 역산** 이었다.

그 사막에서 우리를 가장 여러 번 길 잃게 한 것은 신호가 아니라 **그럴듯한 거짓
가설** 이었다 — self-inflicted `delta=0`, "NCO underrun = 절반?", "추정 소스가
달라서 2×". 매번 우리를 구한 것은 더 영리한 추론이 아니라 **측정** 이었다.
ground truth 와의 한 번의 대조가, 그럴듯한 추론 열 번을 이겼다.

졸업장은 "이제 다 안다"는 증서가 아니다. **"이제 혼자 사막에 들어가도 된다"는
허가증** 이다. 다음 사막 — MSC 의 RS 정정률을 100% 로, 오디오(BSAC)를, 그리고
표준이 침묵한 다음 침묵 — 이 기다린다.

> *암기하지 말고, 데여라. 그리고 데인 자리마다 측정으로 지져라.*
